## 2026-11-19 — Прототип «Обновление ключевых атрибутов» (`key-attributes-update`)
- **Контекст:** задача в системе залогов банка: массово обновить атрибуты предметов залога через файл.
- **Решения:**
  - Статусная модель: Назначена → В работе → Завершена; Отменена. Из «Назначена» в «В работе» — по первому действию (скачивание или загрузка файла). «Завершена» и «Отменена» — только просмотр, кнопки шапки заблокированы.
  - Переназначение: модалка с выбором сотрудника → переход на главную + `notification` справа сверху. Отмена: подтверждение (`Modal.confirm`).
  - Шапка: «Задача №…», тег статуса, строка «Дата · Тип · Ответственный», справа кнопки действий.
  - Вкладка «Обновление атрибутов»: слева постоянная шторка с общей информацией (360px, скрыть нельзя), справа форма. Индикатор шагов не используем.
  - Процесс загрузки: скачать → загрузить → проверка (ошибки: таблица + отчёт) → «Обновить данные» (прогресс; ошибки: отчёт + повтор) → итоговая таблица «тип / всего / обновлено / не обновлено» с итоговой строкой.
  - Необновлённые предметы после успешного обновления — норма, отчёт для них не нужен. Отчёт об ошибках доступен только при ошибках проверки или обновления.
  - Вкладка «Предметы залога»: ID, тип, описание, залогодатель; фильтры в колонках (тип, залогодатель), сортировка по всем колонкам, без поиска и без клика по строке. После завершения задачи значения обновляются.
- **Демо-ветки** (по имени загружаемого файла): `error` → ошибка проверки, `fail` → ошибка обновления.
- **Отказались от:** шагов (`Steps`), поиска по таблице, карточки предмета залога.
