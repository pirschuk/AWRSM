# AWRSM

Проектируем **кликабельные прототипы** внутренних процессов банка (B2B: таблицы, формы, много информации) на базе Ant Design (antd 6, React, TypeScript, Vite). Макеты в Figma не делаем — только прототипы по сценариям. Прототипы сохраняем, обновляем, дополняем, связываем между собой.

## Контекст продукта

- Домен: банк, внутренние процессы. Пользователи — сотрудники банка разных ролей.
- Только десктоп, экран **1920×1080**. Адаптив не делаем.
- Язык интерфейса: **русский** (`ConfigProvider locale={ru_RU}`, dayjs `ru`). Форматы: рубли, даты дд.мм.гггг, русские ФИО.
- Тема: светлая, белый интерфейс, основной акцент — синий. Всё через токены antd.

## Правила дизайн-системы

1. **Только компоненты Ant Design.** Сторонние UI-библиотеки не используем, то, что есть в antd, с нуля не пишем.
2. **Токены** — только antd (`theme.token` в `src/theme.ts`, `ConfigProvider`). Никаких захардкоженных цветов, отступов, радиусов; в стилях — `theme.useToken()`.
3. **Кастомные компоненты** допустимы только на основе готовых antd-компонентов и только после явного обсуждения. Каждый записываем в `docs/custom-components.md`.
4. **Паттерны** — стандартные из antd (https://ant.design/docs/spec/introduce). Отступления проговариваем и записываем в `docs/patterns.md`; следующие экраны делаем с их учётом.
5. Перед созданием интерфейса читаем `docs/custom-components.md`, `docs/patterns.md`, `docs/decisions.md`.
6. Не уверены, есть ли компонент в antd, — сначала смотрим документацию, потом спрашиваем.

## Режимы работы (переключаются командами)

| Команда | Режим |
|---|---|
| `/do <задача>` | **Директивный**: делаю ровно что сказано, без вариантов. Проблемы — одной строкой, но делаю. |
| `/co <задача>` | **Совместный**: бриф → референсы Mobbin → 2–3 варианта с ограничениями antd → выбор → сборка → фиксация. Без выбора пользователя не собираю. |
| `/ref <запрос>` | Только поиск референсов в Mobbin. |
| `/proto <название>` | Новый прототип (папка, сценарий, регистрация, роут). |
| `/shots <что>` | Скриншоты 1920×1080 вариантов/экранов. |
| `/record` | Зафиксировать решения в `docs/`. |
| `/publish` | Сборка, push, GitHub Pages. |

Режим действует, пока не включён другой. Если пользователь пишет без команды — спрашиваю, в каком режиме работаем, если это неочевидно. Нельзя самовольно переходить из `/do` в обсуждение вариантов и обратно.

## Структура

- `src/theme.ts` — токены темы (единственное место настройки темы).
- `src/prototypes/<slug>/` — прототип: `index.tsx`, `scenario.md`, `data.ts` (моки), экраны.
- `src/prototypes/registry.ts` — реестр прототипов (slug, название, статус `draft|review|ready`, связи `linkedTo`).
- Роутинг — `HashRouter` (нужно для GitHub Pages): `/#/<slug>/...`. Связи между прототипами — обычные роутные ссылки.
- `docs/` — `custom-components.md`, `patterns.md`, `decisions.md`, `references.md`, `screens/` (скрины вариантов).

## Стандарты проработки экрана

- Состояния: загрузка, пусто, ошибка, нет прав — где применимо.
- Моки реалистичные: длинные названия, много строк, пустые поля, граничные суммы. Не «Тест 1».
- Таблицы: фиксированные колонки/шапка, пагинация или виртуальный скролл, сортировка/фильтры, плотность `size="small"`/`middle` по месту.
- Формы: валидация на русском, обязательные поля, `Form` antd, группировка секциями.
- Критичные действия (платежи, отказ, удаление) — подтверждение.

## Референсы

Mobbin подключён через MCP (`mcp__Mobbin__*`). Веб-референсов немного — если не нашли, говорим об этом и смотрим ios/смежные паттерны. Каждый референс цитируем ссылкой на `mobbin_url`, записываем в `docs/references.md`.
